# Portfolio working preferences

## Always include a visual preview

For every visual design or UI change, render and inspect the updated result, then include an actual screenshot or image preview directly in the final response. A verbal description, a tool-only image, or a statement that checks passed is not a substitute for the final-response preview.

Show the affected area clearly. Include desktop and mobile previews when the change affects both layouts, and light/dark previews when appearance differs by theme. Use absolute image paths so previews render in chat.

If a preview cannot be generated, explain the specific blocker instead of silently omitting it. State whether the change is local, committed, or published.
